SYSTEM SETUP FOR WINDOWS 10 or 11

This is a brief tutorial on how to setup your personal Windows 10 or 11 64bit Home or Professional system to be ready for the COMS10016 unit.

Before you start make sure Windows 10 or 11 is up-to-date with respect to updates and features.

It is your responsibility to keep your personal system and passwords safe.

TROUBLESHOOTING TIPS

If you have any problems while installing, try these tips:
  • Reread the steps closely: It's easy to skim instructions and assume you know what they're saying, but if you run into problems, make sure to actually read them. You might have missed something important.
  • Turn it off and on again: It might seem silly, but this works ~90% of the time because initialising a program with a valid state is much easier than maintaining a valid state. This could mean restarting a program, the terminal, or even your laptop.
  • Try using a different WiFi network: The most annoying problems are caused by the network, which can be particularly unreliable when 200-300 students are all trying to download a lot of data at the same time in the same place. Try switching from 'eduroam' to 'UoB Guest' (or vice versa), or even using a mobile hotspot if you have a particularly generous data plan (you will need to download gigabytes of data for this setup). You could also try doing the setup in a different place and/or at a different time. There's always the second lab, which should have fewer people.
  • Check your firewall/antivirus/VPN: It could be that your firewall, antivirus, or VPN is blocking network requests. Try temporarily disabling them to see if they're causing the problem. Third-party antivirus software is particularly bad for this sort of thing. The built-in Windows Defender is one of the best antiviruses out there and has the lowest false-positive rate of all of them. For an easy life, you can safely delete your third-party antivirus and switch to Windows Defender instead. If you have McAfee, you should nuke it from orbit.
  • Ask a TA for help: That's what they're there for! They might not know the solution immediately, especially if none of the above helped, but they can help you try to diagnose the problem and work towards a solution.

CHECK SYSTEM COMPATIBILITY

  • Windows search "about" (i.e. hold the Windows key down and simultaneously press "s" so the Windows search bar appears, then type "about" into the search bar).
  • Click "About your PC" in the results and the system specifications window should open.
  • Your system is compatible only if:
    • Your "System type" is "64-bit operating system, x64-based processor".
    • Your system is not in S-Mode and your "Edition" is either "Windows 10 Home" or "Windows 10 Professional" or "Windows 11 Home" or "Windows 11 Professional" without "S Mode". If you need to switch out of S-Mode, follow the instructions on the Microsoft Support Page.
    • If you use Windows 10 then "Version" must be at least 2004, including 20H2, 20H2, 21H1, 21H2. Version 1909 and before are unsupported. If you are running Version 1909 or earlier, you must update your system by going to "Settings -> Update & Security -> Windows Update", then checking for updates and installing any that are available.
  • Ensure virtualisation is enabled on your laptop: The WSL step relies on hardware virtualisation being enabled. This should be enabled by default in the majority of cases, but you can check whether virtualisation is enabled by clicking the Start/Windows button, typing "Windows features", selecting "Turn Windows features on or off", and then see if "Virtual Machine Platform" is enabled/ticked. If it's not, try to enable it. If you can't, follow this guide.
  • Unfortunately, the Chinese Family Edition (家庭中文版) of Windows will not work with the following instructions. This is because it restricts certain virtual machine features. You will have to install a different operating system (e.g. Ubuntu or Windows 11 Home), use a different computer with a supported OS, or use the lab machines. NOTE: Just because your Windows machine is from China or set to Chinese, doesn't mean it won't work. It's specifically 家庭中文版 which doesn't work. Windows 10 or 11 Home or Professional editions should work regardless of where they were purchased or the language settings (though English is appreciated, for the benefit of our TAs trying to help you).

ACTIVATE WSL2 (WINDOWS SUBSYSTEM FOR LINUX) IN WINDOWS 10 or 11

  • Windows search "powershell".
  • Right-click "Windows PowerShell" (not "Windows Powershell (x86)") and click "Run as administrator".
  • Click yes on the consent prompt and an elevated PowerShell will open.
  • Make sure WSL is updated: wsl --update
    • If PowerShell can't find the wsl command, make sure your Windows is fully updated, then try again. If it still isn't there, make sure PowerShell is in 64-bit mode by running [Environment]::Is64BitProcess (which will return "True" if it is and "False" if it isn't).
  • In PowerShell, run wsl --set-default-version 2 (i.e. type "wsl --set-default-version 2" and press enter), then run wsl --install -d Ubuntu.
  • As part of the installation, you will be prompted to create a default Unix user account name and password. Make sure you remember them. You can use any username, but many people just use their name in lowercase (eg. "tilo"). Important: When you enter your password it won't display any characters as you type. This is not a bug, your password is still being entered.
  • You will be asked to opt-in to platform metrics collection. We recommend opting out by entering 'n' (for 'no') instead of the default 'y' (for 'yes'). You may opt-in if you want to, however.
  • If an Ubuntu window opens immediately, just continue to the next step. If you're prompted to restart your computer, do so. Soon after your computer reboots, an Ubuntu window should open and complete the installation process. This may take a few minutes.
  • Update Ubuntu by running sudo apt update (this checks for upgrades), then sudo apt upgrade (this installs the upgrades). When asked "Do you want to continue? [Y/n]", press enter to select the default "Y"/"Yes" option, and wait for the upgrade to complete. [Side note: apt is a "package manager", which does what it says on the tin and manages packages/software on your system. sudo stands for "SuperUser DO" and you add it to the front of a command to run that command as the superuser (a.k.a. administrator or "root").]
  • Your Ubuntu files are stored in a separate filesystem to your Windows files, which makes difficult to access from Windows (and you shouldn't try to). However, you can access your Windows C drive from Ubuntu by going to the "/mnt/c" directory in the Ubuntu terminal (if your Windows is on the D drive, it would be "/mnt/d" instead etc.). For convenience, you can create a "symbolic link" (similar to a shortcut) from your Linux home directory to your Windows files by running: ln -s /mnt/c/Users/[insert your Windows username here]/Documents ~/WindowsDocuments (e.g. ln -s /mnt/c/Users/tilo/Documents ~/WindowsDocuments)
  • Whenever you want to open a new Ubuntu terminal, you can Windows search "Ubuntu" and click the Ubuntu application.

INSTALL THE CLANG COMPILER

  • In an Ubuntu terminal, run sudo apt install clang

INSTALL HASKELL

  • In an Ubuntu terminal, first install the dependencies for GHCup by running sudo apt update then sudo apt install build-essential curl libffi-dev libffi8 libgmp-dev libgmp10 libncurses-dev pkg-config
    • To copy-paste into the terminal, copy the text as normal with Ctrl + C, then Right Click in the terminal (this can be a little bit unreliable, just keep recopying and pasting until it works)
  • Once that's done, use GHCup to install the Haskell tools we need by running curl --proto '=https' --tlsv1.2 -sSf https://get-ghcup.haskell.org | BOOTSTRAP_HASKELL_NONINTERACTIVE=y BOOTSTRAP_HASKELL_GHC_VERSION=9.14.1 BOOTSTRAP_HASKELL_CABAL_VERSION=3.16.1.0 BOOTSTRAP_HASKELL_INSTALL_NO_STACK=y BOOTSTRAP_HASKELL_INSTALL_HLS=y BOOTSTRAP_HASKELL_HLS_VERSION=2.14.0.0 BOOTSTRAP_HASKELL_ADJUST_BASHRC=y sh
    • Make sure you copy the whole command in one go, from "curl" all the way to "sh"
    • This will take some time and is the step most likely to fail due to network problems. See the Troubleshooting Tips section if this happens.
  • Once the previous step completes successfully, you'll need to restart your terminal. [Side note: This is because your default PATH variable has been modified and needs to be reinitialised. Your PATH variable contains a list of directories your terminal will look through to find executables, e.g. when you use curl as a command, your terminal looks for an executable named "curl" in those directories. GHCup creates a new directory where it will put executables, so this has to be added to your PATH if you want to use them in your terminal.]
  • You should now have ghc (the Haskell compiler), ghci (the Haskell REPL), cabal (a Haskell package manager), and the Haskell Language Server (a.k.a. HLS, which adds IDE support for Haskell)
  • Check they're working by running ghc --version, ghci --version, cabal --version, and haskell-language-server-wrapper --version. If they've installed correctly, each of these commands should print out version information.
  • Update cabal's package list by running cabal update

INSTALL THE VSCODE EDITOR

  • Go to https://code.visualstudio.com/
  • Download and run the installer for Windows.
  • During installation, under the Additional Tasks step, ensure all the checkboxes under "Other:" are checked.
  • Once VSCode is installed, open it and DO NOT SIGN IN if prompted. Close the prompt by clicking the 'X' in the top right corner of the prompt instead. If another 'Sign in to use GitHub Copilot' prompt pops up, close that as well. DO NOT SIGN IN.
  • Press Ctrl + ',' or click "File -> Preferences -> Settings" to open the Settings menu. Search for 'chat.disableAIFeatures' and click the 'Disable AI Features' checkbox.
  • We also recommend disabling telemetry (i.e. automatically sending Microsoft your usage data). To do this, open the Settings menu and search "telemetry.telemetryLevel", then set the dropdown menu to 'off'. You may need to restart VSCode after changing this setting.
  • Install the "Remote - WSL" extension by pressing Ctrl + P and then entering "ext install ms-vscode-remote.remote-wsl".
  • Whenever using VSCode, make sure you're using a WSL window. The easiest way to do that is to look in the bottom-left corner of the window. If it's using WSL, it will say "WSL: Ubuntu". If it doesn't say that, click it and select "Connect to WSL" to open a WSL Window. If you already have a folder open in VSCode, use Ctrl + Shift + P to open the command palette, then type "WSL: Reopen Folder in WSL" and press enter. For more detailed information, see: Developing in WSL
  • You can open an Ubuntu/WSL terminal from within a VSCode WSL window with "Terminal -> New Terminal" (the "Terminal" button might be hiding under the "..." next to "File", "Edit" etc. if your VSCode window is too small to show all the options).
  • Make sure your VSCode window is in WSL mode, then open and install the "Haskell" extension by pressing Ctrl + P and entering "ext install haskell.haskell". It's important you do this in a WSL window, because it relies on GHCup, which is installed on WSL, not on Windows. If asked 'Do you trust the publisher "Haskell"?' select 'Trust Publisher & Install'.
  • Test HLS is working by creating a new Haskell file named "test.hs" (e.g. with "File -> New File" and naming it "test.hs"). This might give you a prompt saying "How do you want the extension to manage/discover HLS and the relevant toolchain?". Select "Automatically via GHCup".
  • If it says "Need to download stack, continue?", click "No". We will not be using stack, so this will just take up unnecessary bandwidth in the setup lab. If it comes up again in the future, feel free to click "Yes" just to make the pop-up go away.
  • In "test.hs", start typing some invalid Haskell code, e.g. x = True && 'c'. If HLS is working, you should see that VSCode underlines the error. You might need to give it a little bit of time to load.

SET UP SEARCH ENGINES (OPTIONAL)

Chrome / Chromium

  • "..." -> Settings -> Search engine -> Manage search engines and site search
  • To the right of "Site search", click "Add" and add each of the following:
    • DuckDuckGo (Private searches and no AI results)
      • Name: NoAI DuckDuckGo
      • Shortcut: noai.duckduckgo.com
      • URL with %s in place of query: https://noai.duckduckgo.com/?q=%s
      • Suggestions URL with %s in place of query: https://noai.duckduckgo.com/ac/?q=%s&type=list
    • Hoogle (Haskell API search engine)
      • Name: Hoogle
      • Shortcut: h
      • URL with %s in place of query: https://hoogle.haskell.org/?hoogle=%s
      • Leave 'Suggestions URL with %s in place of query' blank
  • To the right of "NoAI DuckDuckGo", click '"..." -> Make default' to make it your default search engine
  • Now, normal searches will go through DuckDuckGo and typing 'h' + Space will search Hoogle.

Firefox (and derivatives)

  • Burger menu/"|||" -> Settings -> Search -> Additional search engines -> Add search engine
  • Add each of the following:
    • DuckDuckGo (Private searches and no AI results)
      • Search engine name: NoAI DuckDuckGo
      • URL with %s in place of search term: https://noai.duckduckgo.com/?q=%s
      • (Click Advanced) Suggestions URL with %s in place of search term: https://noai.duckduckgo.com/ac/?q=%s&type=list
    • Hoogle (Haskell API search engine)
      • Search engine name: Hoogle
      • URL with %s in place of search term: https://hoogle.haskell.org/?hoogle=%s
      • Keyword: h
  • Under "Default search engine" select "NoAI DuckDuckGo"
  • Now, normal searches will go through DuckDuckGo and typing 'h' + Space will search Hoogle.

At this point your system is ready for most of the COMS10016 unit and you are ready to start programming in C and Haskell. Further installations are optional at the beginning of the unit. However, during the last part of the unit we will use graphics, and for this we will need the SDL2 graphics libraries.

INSTALL THE SDL2 DEVELOPMENT PACKAGE

  • In an Ubuntu terminal, run sudo apt install libsdl2-dev

CHECKING SDL2

  • Download the program hellosdl.cby running the following in a WSL terminal: curl -o hellosdl.c https://uob-coms10016.github.io/2026/hellosdl.c
  • Compile the program by running clang -std=c11 -Wall hellosdl.c -I /usr/include/SDL2 -l SDL2 -o hellosdl , where the 'I' (uppercase i) in -I /usr/include/SDL2 stands for "Include" and the 'l' (lowercase L) in -l SDL2 stands for "link".
  • If the compilation was sucessful, you will see the new executable file hellosdl in the current directory. You can check this by running the ls command to list the contents of the current folder.
  • Run the compiled program by running ./hellosdl - if you see a sky blue window appear then SDL2 is working properly!
  • Note that some parts of the SDL library unfortunately have memory leaks, but there's nothing you can do about them, so don't be alarmed if you see some warnings.
