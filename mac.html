COMS10016 | Week 01 | Preparation

SYSTEM SETUP FOR OSX

This is a brief tutorial on how to setup your personal Apple/Mac/OSX system to be ready for the COMS10016 unit. Before you start make sure your system is up-to-date with respect to updates and features. It is your responsibility to keep your personal system and passwords safe. To ensure your Mac user has the required permissions, go to "System Preferences > Users & Groups". Ensure that your user account is listed as 'Admin', otherwise log in with an Admin account.

TROUBLESHOOTING TIPS

If you have any problems while installing, try these tips:
  • Reread the steps closely: It's easy to skim instructions and assume you know what they're saying, but if you run into problems, make sure to actually read them. You might have missed something important.
  • Turn it off and on again: It might seem silly, but this works ~90% of the time because initialising a program with a valid state is much easier than maintaining a valid state. This could mean restarting a program, the terminal, or even your laptop.
  • Try using a different WiFi network: The most annoying problems are caused by the network, which can be particularly unreliable when 200-300 students are all trying to download a lot of data at the same time in the same place. Try switching from 'eduroam' to 'UoB Guest' (or vice versa), or even using a mobile hotspot if you have a particularly generous data plan (you will need to download gigabytes of data for this setup). You could also try doing the setup in a different place and/or at a different time. There's always the second lab, which should have fewer people.
  • Check your firewall/antivirus/VPN: It could be that your firewall, antivirus, or VPN is blocking network requests. Try temporarily disabling them to see if they're causing the problem.
  • Ask a TA for help: That's what they're there for! They might not know the solution immediately, especially if none of the above helped, but they can help you try to diagnose the problem and work towards a solution.

INSTALL THE CLANG COMPILER

  1. Open the Terminal (Mac command prompt). For example, press Command + Space and type: 'Terminal' then select Terminal - a Terminal window will open.
  2. Run clang --version to see if the C compiler is already available.
    You should get ONE of the following responses:
    • Information shown such as 'Apple clang version 17.0.0 (...)'.
      The compiler is already installed, move on to Installing the VSCode Editor.
    • OR: A dialogue box pops up suggesting you install the Command Line Developer Tools.
      Select Install and follow the wizard steps to install these Tools. This may take a long time.
      After this is complete, again run: clang --version
      You should now get output as above.
    • OR: An error showing that the command is not found.
      Enter: xcode-select --install to start the Command Line Developer Tools install dialogue - follow instructions as above.
    If all of that fails, as a last resort install 'Xcode' from the App Store on your Mac.

INSTALL HOMEBREW

  • In a terminal, run brew to check if the Homebrew package manager is already installed.
  • If a 'command not found' error is shown, run the following command in your terminal and follow the instructions:
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  • If you encounter a permissions issue on your device you may want to check out this discussion.
  • In case you missed them, run the commands in the "Next steps" section after the installation finishes, which are:
    1. echo >> ~/.zprofile
    2. echo 'eval "$(/opt/homebrew/bin/brew shellenv zsh)"' >> ~/.zprofile
    3. eval "$(/opt/homebrew/bin/brew shellenv zsh)"
  • Run:
    1. brew analytics off
    2. brew update
    3. brew upgrade

INSTALL HASKELL

  • Use GHCup to install the Haskell tools we need by running curl --proto '=https' --tlsv1.2 -sSf https://get-ghcup.haskell.org | BOOTSTRAP_HASKELL_NONINTERACTIVE=y BOOTSTRAP_HASKELL_GHC_VERSION=9.14.1 BOOTSTRAP_HASKELL_CABAL_VERSION=3.16.1.0 BOOTSTRAP_HASKELL_INSTALL_NO_STACK=y BOOTSTRAP_HASKELL_INSTALL_HLS=y BOOTSTRAP_HASKELL_HLS_VERSION=2.14.0.0 BOOTSTRAP_HASKELL_ADJUST_BASHRC=y sh
    • Make sure you copy the whole command in one go, from "curl" all the way to "sh"
    • This will take some time and is the step most likely to fail due to network problems. See the Troubleshooting Tips section if this happens.
  • Once the previous step completes successfully, you'll need to restart your terminal. [Side note: This is because your default PATH variable has been modified and needs to be reinitialised. Your PATH variable contains a list of directories your terminal will look through to find executables, e.g. when you use curl as a command, your terminal looks for an executable named "curl" in those directories. GHCup creates a new directory where it will put executables, so this has to be added to your PATH if you want to use them in your terminal.]
  • You should now have ghc (the Haskell compiler), ghci (the Haskell REPL), cabal (a Haskell package manager), and the Haskell Language Server (a.k.a. HLS, which adds IDE support for Haskell)
  • Check they're working by running ghc --version, ghci --version, cabal --version, and haskell-language-server-wrapper --version. If they've installed correctly, each of these commands should print out version information.
  • Update cabal's package list by running cabal update

INSTALL THE VSCODE EDITOR

  • In your web browser, navigate to: https://code.visualstudio.com/docs/setup/mac
  • Follow the 'Install VS Code on macOS' and 'Launch VS Code from the command line' instructions, but when you open a VSCode window DO NOT SIGN IN if prompted. Close the prompt by clicking the 'X' in the top right corner of the prompt instead. If another 'Sign in to use GitHub Copilot' prompt pops up, close that as well. DO NOT SIGN IN.
  • Press Cmd + ',' or click "Code -> Preferences -> Settings" to open the Settings menu. Search for 'chat.disableAIFeatures' and click the 'Disable AI Features' checkbox.
  • We also recommend disabling telemetry (i.e. automatically sending Microsoft your usage data). To do this, open the Settings menu and search "telemetry.telemetryLevel", then set the dropdown menu to 'off'. You may need to restart VSCode after changing this setting.
  • Install the "Haskell" extension by pressing Cmd + P and entering "ext install haskell.haskell". If asked 'Do you trust the publisher "Haskell"?' select 'Trust Publisher & Install'.
  • Test HLS is working by creating a new Haskell file named "test.hs" (e.g. with "File -> New File" and naming it "test.hs"). This might give you a prompt saying "How do you want the extension to manage/discover HLS and the relevant toolchain?". Select "Automatically via GHCup".
  • If it says "Need to download stack, continue?", click "No". We will not be using stack, so this will just take up unnecessary bandwidth in the setup lab. If it comes up again in the future, feel free to click "Yes" just to make the pop-up go away.
  • In "test.hs", start typing some invalid Haskell code, e.g. x = True && 'c'. If HLS is working, you should see that VSCode underlines the error. You might need to give it a little bit of time to load.

SET UP SEARCH ENGINES

Safari

  • 'Safari -> Settings -> Search' and in the 'Search engine' dropdown, select 'DuckDuckGo'.
  • Safari doesn't allow custom search engines unfortunately, but you can use DuckDuckGo's !Bangs feature which redirects your search to other engines. To search Hoogle, start your search with '!h ', e.g. '!h map'

Chrome / Chromium

  • "..." -> Settings -> Search engine -> Manage search engines and site search
  • To the right of "Site search", click "Add" and add each of the following:
    • DuckDuckGo (Private searches and no AI results)
      • Name: NoAI DuckDuckGo
      • Shortcut: noai.duckduckgo.com
      • URL with %s in place of query: https://noai.duckduckgo.com/?q=%s
      • Suggestions URL with %s in place of query: https://noai.duckduckgo.com/ac/?q=%s&type=list
    • Hoogle (Haskell API search engine)
      • Name: Hoogle
      • Shortcut: h
      • URL with %s in place of query: https://hoogle.haskell.org/?hoogle=%s
      • Leave 'Suggestions URL with %s in place of query' blank
  • To the right of "NoAI DuckDuckGo", click '"..." -> Make default' to make it your default search engine
  • Now, normal searches will go through DuckDuckGo and typing 'h' + Space will search Hoogle.

Firefox (and derivatives)

  • Burger menu/"|||" -> Settings -> Search -> Additional search engines -> Add search engine
  • Add each of the following:
    • DuckDuckGo (Private searches and no AI results)
      • Search engine name: NoAI DuckDuckGo
      • URL with %s in place of search term: https://noai.duckduckgo.com/?q=%s
      • (Click Advanced) Suggestions URL with %s in place of search term: https://noai.duckduckgo.com/ac/?q=%s&type=list
    • Hoogle (Haskell API search engine)
      • Search engine name: Hoogle
      • URL with %s in place of search term: https://hoogle.haskell.org/?hoogle=%s
      • Keyword: h
  • Under "Default search engine" select "NoAI DuckDuckGo"
  • Now, normal searches will go through DuckDuckGo and typing 'h' + Space will search Hoogle.
At this point your system is ready for most of the COMS10016 unit and you are ready to start programming in C and Haskell. Further installations are optional at the beginning of the unit. However, during the last part of the unit we will use graphics, and for this we will need the SDL2 graphics libraries and a Linux desktop environment...

INSTALL THE SDL2 DEVELOPMENT PACKAGE

  • In a terminal, run: brew install sdl2
  • Ensure SDL2 is installed by running: sdl2-config --version (version information should be displayed, such as 2.24.0).
  • Install pkg-config to make compiling with SDL2 easier: brew install pkg-config

CHECK SDL2 GRAPHICS

  • Download the program hellosdl.c by running: curl -o hellosdl.c https://uob-coms10016.github.io/2026/hellosdl.c
  • Compile the program: clang -std=c11 -Wall hellosdl.c -o hellosdl `pkg-config --libs --cflags sdl2`
  • If the compilation was successful, you will see the new executable file hellosdl in the current directory. You can check this by running the ls command to list the contents of the current folder.
  • Run this program by running: ./hellosdl
  • If you see a sky blue 'Hello SDL2' window appear then SDL2 is working properly!
  • Note that some parts of the SDL library unfortunately have memory leaks, but there's nothing you can do about them, so don't be alarmed if you see some warnings.
